# File access, worktrees and web auth

## Worktrees and project grouping
- `lib/worktree.ts` resolves linked worktree top-levels to the main repo `projectRoot`; `listAllSessions()` attaches it to each `SessionInfo`, so a repo's worktrees group together in the sidebar. A session whose cwd is a removed worktree is inferred back into the main project, never a phantom project row. `/api/models` resolves a cwd that is gone the same way (a finished sub-agent run removes its worktree, and its session still names it) and re-checks the repo it falls back to against the allowed roots, so the fallback only ever answers for a project that was already allowed. `/api/project-trust` does not fall back: trust is per path, the repo's decision is not the removed folder's, and trusting a folder that is gone is refused, so a GET answering for the repo would only offer a Trust button that fails.
- `resolveProject()` caches each cwd's identity for a minute, then serves it stale while git runs again. A cold lookup and a stale refresh of the same cwd share one in-flight promise (`refreshProject()`; `invalidateProjectCache()` drops it), and the existence and canonical-path checks are asynchronous, so a session list fanning out over many cwds neither spawns git twice per cwd nor blocks the event loop on `existsSync` / `realpathSync`. A git run that never answered (a spawn out of fds, processes or memory, or git killed by the timeout) is never cached: that request alone gets the cwd as its own project, the next one asks again, and a background refresh keeps the stale identity. Whatever git itself exits with (outside a repository, at a mount point, dubious ownership, a broken `.git`), and a missing git, is the cwd's answer and cached, so a broken cwd does not spawn git and log on every session list. Classify by spawn error code and kill, never by git's message text.
- The root is the folder holding the common git dir only when that dir is its `.git`, or a bare repo a `.git` file there points at (`project/.bare`). Any other bare clone (`parent/repo.git`) is its own root (#1049): its parent may hold other clones, whose worktrees would all fall into one project, and that parent would become an allowed file root. `addWorktree()` uses the same root, so a bare clone's new worktrees go to `repo.git-worktrees/`.
- `/api/worktrees` serves worktree operations under the same allowed-root rules as `/api/files`. New worktrees go under `<repoRoot>-worktrees/<sanitized-branch>`; an existing branch is reused, else `git worktree add -b` creates it. A branch another worktree has checked out (git checks one out once; one pi-web made also has the new one's folder) answers 409 `branch_in_use` with that worktree's path, looked up in git's whole worktree list before the folder check; an entry whose folder is gone (deleted by hand) still holds the branch and answers `branch_worktree_missing`, whose message says `git worktree prune` clears it (never run for the user). The form shows both translated (`worktreeCreateFailure()`, #1431). Removing a dirty worktree answers `409 { dirty: true }`, and the UI asks before retrying with `force`.
- Two places switch or create worktrees, one component (`components/ProjectWorktreePicker.tsx`) on the sidebar's one listing of its cwd (`GET /api/worktrees?cwd=`, refetched when the cwd moves). The files' worktree box (the section below the sessions or the Files tab, whichever the layout shows; in the head above the explorer, beside the project box below the sessions, under it in the tab) switches, creates and removes; it shows at the top of a git checkout, a disabled box says why in a subdirectory of one (its root has the worktrees), and a folder outside any repository has no worktree box at all, the project box taking the whole width (the listing's `isGit` tells the two apart). A folder the listing last found outside git shows no "checking" box while it is listed again, which would only go and widen the project box: the browser keeps the last 50 such folders (`loadNonGitCwds()` / `rememberCwdGitStatus()` in `lib/sidebar-prefs.ts`, read-modify-write so other tabs' stay; one found in git leaves), so a reload knows them before its listing answers, the default dated folder included; only a folder this browser never listed shows the box once. The bar above a fresh composer (`components/NewSessionContextBar.tsx`) shows the same list under the same rule, and removes nothing. Both create through the sidebar (`createWorktree()`, also `SessionSidebarControl.createWorktree()`: `POST` with the project root); the files' picker then moves the sidebar's cwd there, the bar starts the new session there; opening either menu refetches the listing. Removal is `DELETE` with the project root; a dirty checkout answers 409 `dirty` and the picker asks before `force`. A group's "+" asks nothing: it starts in the current worktree or another project's root. Every GET `allowFileRoot()`s each listed worktree (the in-memory grant from `addWorktree` does not survive a restart), so a worktree picked there is browsable before it has a session. Clicking a session still moves the cwd to its worktree implicitly.
- The sidebar names its cwd's project with `projectForCwd()` (`lib/new-session-context.ts`): a folder it just validated, the listing of that cwd, a checkout in the listing, then the session list. The listing is still the previous cwd's for the commit after a move, and its checkouts count only when it is a checkout's (`isTopLevel`): a subdirectory's lists the repo's checkouts under the subdirectory's own key, so a click on a root session right after it gave that session the subdirectory's key, and `handleCwdChange` closed it as a project switch and rewrote the URL to `/` (#1289).
- git prints POSIX-style absolute paths even on Windows: every path read from git goes through `toNativePath()` (`lib/paths.ts`) before it is compared or returned, and paths are compared with `samePath()`, never `===` (otherwise `isTopLevel` is always false on Windows and the worktree switcher hides). Branch names are not paths and keep their forward slashes. Browser code cannot apply Node path rules, so `/api/worktrees` resolves `currentWorktreePath` server-side and the sidebar uses it for highlighting and the removal fallback.
- `git rev-parse --show-toplevel` answers with the repository's real path, while the cwd a caller gives may reach it through a link (`/tmp` and `/var/folders/…` are links on macOS): `lib/worktree.ts` compares the two with `resolveExistingPath()` (`lib/paths.ts`, the nearest existing ancestor resolved and the rest kept as written), so a project behind a link is still one project.

## Directory picker (`components/DirectoryPicker.tsx`)
- The path field browses only on Enter/"Go"; that, a row, the parent arrow, a drive and a created folder list the folder and rewrite the field to the browse route's `realpath`. When the field holds other text, "Select this folder" needs no Go first: it browses the text as Go does and selects the listed `realpath`, which the sidebar validates like any selection (`commitCustomPath()` → `/api/cwd/validate`). Never send the typed text to validate itself: that route only expands `~` and resolves relative paths, so a case variant, a link, `..` or a trailing slash would become a second cwd, project group and pi session directory for one folder, one pi's TUI (`process.cwd()`, the physical path) never reads. A path that cannot be listed shows Go's error and the picker stays open; a Select cancelled while it browses selects nothing. "New directory" still needs the field to match the list, since it creates inside the listed folder.
- Select and Go are disabled while they check, which drops focus to `<body>`, where Escape stops the running agent (`handleGlobalEscape()`) instead of closing the picker: a refusal puts focus back in the path field.
- Never browse the field as it is typed (#461 declined, #1550 shrunk to the above): that sends a request and shows an error for every paused prefix (`/U`, `/Us`…), and its answers race the explicit moves.

## File access allow-list
- `/api/files` is the chat's media and upload pipe, not a filesystem browser. Allowed roots: session cwds, their resolved project roots, and roots added with `allowFileRoot()`, which `/api/cwd/validate` and `/api/worktrees` call when they make a location browsable. "Use default directory" too: `/api/default-cwd` only creates `~/pi-cwd/YYYYMMDD`, and the sidebar selects it through `/api/cwd/validate`.
- `isPathWithinRoots()` (`lib/path-security.ts`) is the single implementation behind `isFilePathAllowed()` and is the security boundary: keep it the only one. It re-resolves and case-folds both sides, so either path form authorizes; roots are stored slash-normalized only as a Set-key convention.
- `isExistingPathWithinRoots()` resolves the target, then tries the roots that hold it lexically before the rest, stopping at the first canonical match; only canonical containment grants access (a link can land in another root), and `realpath` results are never cached across requests. It used to `realpath` every allowed root on every file request.
- `isExistingPathWithinRoots()` refuses any path with a `..` segment (`hasParentDirectorySegment()`: authorization collapses `..` before following links, the filesystem after). Query-string and body paths reach that check verbatim. In `/api/files/[...path]` URL parsing drops literal `..` segments, and the route itself refuses an encoded slash inside a segment (`link%2F..%2Fx`), because a session-referenced file skips the existing-path check.
- `/api/files/...?sessionId=` also reads (never lists) a file outside the roots when that exact path appears in the session, so a chat link opens (`lib/session-file-references-core.ts`). Never counted: transcript system messages, the codemode script store, `context_edit` replacements, and the result of any tool but pi's coding tools (codemode and third-party extensions relay remote-controlled text). Such a result still authorizes its `details.fullOutputPath` and the arguments of the coding-tool calls it made through `ctx.executeTool()` (`nestedCalls`), never those of its nested tool calls. User and assistant messages, the model's own tool-call arguments and the other entries count. Tools are matched by name: keep the list in step with `CODING_TOOL_NAMES`.
- `proxy.ts` refuses cross-site browser requests to `/api/*` (`isApiRequestAllowed()`, `lib/request-security.ts`). The one file exception is a user-activated top-level GET (`navigate` + `document` + `Sec-Fetch-User: ?1`) of `type=read` on a `.pdf` (#1298): Android Chrome does not render a PDF in the viewer's iframe and shows a `data:` placeholder whose Open link arrives cross-site with no Origin. The route serves a `.pdf` only as `application/pdf` with nosniff, so the tab runs no script in the Pi Web origin and the opener cannot read it; never widen this to another `type` or extension (HTML, SVG, `watch`), and keep iframe/embed destinations refused.
- A UNC cwd (`\\host\share\dir`) must survive the `/api/files/[...path]` round-trip: `encodeFilePathForApi()` folds the `//` root into the first segment (`%2F%2Fhost`) and `filePathFromApiSegments()` decodes it back. Never split a UNC path into segments and rejoin them: `\\host\share` becomes a relative-looking `host/share` and every allow-check answers 403.
- What the `@` index leaves out is visibility, never access: hidden entries stay reachable by path. `lib/file-tree-visibility.ts` asks one `git check-ignore --no-index --stdin` per listing, then one `git ls-files` which matched names hold a tracked path; those stay listed. Never let check-ignore consult the index (one whole-index scan per name). `.git` and `.DS_Store` are always hidden. The fixed name list (`node_modules`, `dist`, `build`, …) applies only where Git has no view: outside a work tree, when git fails or times out (5 s), and inside an ignored directory with nothing tracked below it. Names go to check-ignore as `./name` and to ls-files under `--literal-pathspecs`. Both calls pass `-c core.fsmonitor=false`, or expanding a folder runs a hook the repository configured. Every git child that runs in a project folder (these, `lib/git-changes.ts`, `lib/worktree.ts`, `/api/file-index`) gets `projectGitEnvironment()`: the host environment without `PORT`, `NODE_ENV`, `NEXT_*` and `PI_WEB_PASSWORD` (ADR 0001) and `LC_ALL=C`, since a hook the repository configures (the cwd's own `core.fsmonitor`, which `getGitStatus()` keeps running) inherits it.
- Every filesystem call that reaches a **runtime** path (a session file, a cwd, `models.json`, a worktree) carries `/*turbopackIgnore: true*/` on its path argument: without it Turbopack's build traces the whole project into the server output (13 "Dynamic filesystem access" warnings, and a bigger deployment). `lib/pi-sdk-internals.ts` marks its runtime `import()` the same way, with `webpackIgnore` beside it; a path the bundler cannot see at build time must never be resolved by it.

## What `/api/files` serves now
- `GET /api/files/<path>?type=read` streams media only: an image (up to 10 MB), audio, a video or a document, which is what the chat's Markdown renders (`MarkdownBody`'s `MarkdownImage` for images, audio and video, with range requests). Any other file answers 415: the app has no text viewer, so text is read in an editor, not here. Nothing lists, downloads or watches files any more (the file browser, the file preview and the terminal were removed with their routes).
- `POST /api/files/<cwd>?type=upload` is the one write path: a chat drop or the composer's attach button (`uploadFiles()`, `lib/file-upload-client.ts`). It goes straight to `conflict=skip`, so it never replaces a file, and inserts `@name` for every file the response lists as uploaded *or* skipped.
- `GET /api/file-index?cwd=` still lists the project's files for the composer's `@` autocomplete, through `lib/file-tree-visibility.ts` (the hidden-name and Git-ignored rules) and `lib/file-fuzzy.ts`.

## Uploads and chat drops
- A non-image file dropped onto the chat goes through `uploadFiles()` and `POST /api/files/<cwd>?type=upload`; never add a second write path for drops. It then inserts `@name` for every file the response lists as uploaded *or* skipped (a skipped name is a file already there, often the very file dragged out of the project) and says in a notice that the mention points to the existing file.
- Dropped images still attach to the prompt, as the original bytes (up to `MAX_ATTACHED_IMAGE_BYTES`, 10MB): the browser never resizes or re-encodes them. pi resizes prompt images itself in `_normalizePromptImages()`, following `images.autoResize` and the model's `inputLimits.images.resize`. Folders are left out with a notice: the endpoint writes flat file names only (`validateUploadFileNames()`), and the browser cannot tell where a dropped file lives on disk, so the copy always lands in the cwd root.
- The composer's attach button (#1101, for phones that cannot drop) is a drop by another route: its file input has no `accept` list (and no `capture`, so phones still offer photos and the camera), and `ChatInput` hands the whole selection to ChatWindow's `onAttachFiles`, which calls the drop handler. Images attach, other files upload and get mentioned, with the same notices; keep one path for both. A `ChatInput` without `onAttachFiles` keeps `accept="image/*"`.

## Web password throttling
- `lib/auth-throttle.ts` is deliberately global, not per-IP (its header says why). Failures double the delay (1 s → 60 s cap) for everyone; a success or 5 idle minutes resets it. The reset window must stay longer than the max delay, or waiting out one block restarts the burst.
- State lives on `globalThis` under `Symbol.for("pi-web:auth-throttle")`, so it survives hot reload and `proxy.ts` and the route handlers share it under both `next dev` and `next start`. Tests reset it with `recordAuthSuccess()`.
- `POST /api/web-auth` and every `Authorization: Basic` header on `/api/*` share the counter; `proxy.ts` checks Basic before its `/api/web-auth` exemption, so `GET /api/web-auth` is no unthrottled password oracle. A valid session cookie is checked first and never blocked. While blocked, Basic gets `429` even with the right password, and a Basic success never resets the counter (`proxy.ts` explains both).
- Check, compare and record must run in one synchronous stretch, or attempts sent together all pass the check before the first failure lands. `proxy.ts`'s Basic path never awaits between them; `POST /api/web-auth` therefore reads its body before `getAuthRetryAfterMs()`, not after (with the check first, a burst of 20 wrong guesses and the right password all got compared, and the last one logged in).
